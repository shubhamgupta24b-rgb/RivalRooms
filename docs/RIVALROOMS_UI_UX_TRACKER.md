### Online
The Flutter Play online tab still explains that room creation, joining, and quick play need a client connection. No Flutter game is online. The Node server does have Socket.IO rooms, disconnect grace, and authoritative handlers for its own games (including memory, Guess Who, Raja Mantri, and several others). `math_duel` and `connect_four` on the server are relay ids: the host publishes state. That is not the same as the local Flutter rules, and the app does not join those rooms.

### Backend and Render
- Listens on `process.env.PORT` or 3000, host `process.env.HOST` or `0.0.0.0`.
- `/health` returns 200 `{ok:true, app:"rivalrooms", db:"disabled"|"connected"}` when the process can serve rooms. If `MONGO_URI` is set and the connection fails, `/health` returns 503 and `db:"error"`. Mongo is optional; profiles and the leaderboard stay off when it is unset.
- `render.yaml` is a native Node web service, not Docker. Root directory `server`, build `npm ci`, start `npm start`, health check `/health`.
- Required for the current production config in `render.yaml`: `NODE_ENV=production`, `AUTH_MODE=dev`, `ALLOW_DEV_AUTH=true` (dev auth is refused in production without that flag), and `PRIVACY_CONTACT` supplied in the Render dashboard. Optional: `MONGO_URI`, `PORT`, `HOST`, `CORS_ORIGIN`, `RECONNECT_GRACE_MS`, `FIREBASE_PROJECT_ID`, `GOOGLE_APPLICATION_CREDENTIALS`. No real secrets are committed. See `server/.env.example`.
- This session did not deploy to Render. Dashboard steps: Render → New → Blueprint → this repository, or New Web Service with root `server`, build `npm ci`, start `npm start`. Confirm `/health` on the live URL before calling it deployed.
